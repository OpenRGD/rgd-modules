# EXT-01B — Registry-side release proposal review

**Candidate / maintainer-only / offline.** Stacked on REG-INDEX-01 #3 at 8c50645b6fbc73d73a87a278bf2009fa83f3705d. Consumes the exact Core EXT-01B candidate [PR #19](https://github.com/OpenRGD/openrgd/pull/19), commit `46fd178d2ccccdfb46f91d3cdafec1456dec5147`; no copied schema, no second producer declaration, no runtime dependency. The existing v0.1 catalog, Calibration descriptor, index and installation code are unchanged.

The official registry owns publication, not declaration. `tools/review_publication.py` is a review-only reference bridge: independently recompute the proposed commitments using Core's exact proposal validator on the supplied producer manifest/descriptor/artifact bytes and source claim, compare with the submitted proposal, reject if the existing v0.1 catalog already contains that release key. An existing legacy release cannot be compared to the new profile by ID or source pin alone. Unique proposed keys are still **review_required**, never automatically published or installable. No write of an index, no new descriptor, no loader, process start, fetch, hardware or grant.

Use only with a trusted, separately checked exact Core checkout; CI sets the pinned Core candidate directory and this Registry checkout on PYTHONPATH. This prototype exposes a maintainer Python function (not a production CLI/API); future packaging of the shared protocol library must be reviewed. It does not load arbitrary provider Python or interpret a source URI as a command or location. Tests pass actual recovered historical example bytes and synthetic artifact bytes, not real wheels/binaries. The proposal's raw-byte commitments and exact legacy profile checks are not authentication of the publisher, Git tree membership, artifact format, safety or host compatibility.

A real release transaction still needs verified namespace/delegation, exact source/artifact retrieval, artifact format/provenance validation, recovered semantic validator and real producer/consumer conformance, accepted release schema and independent publication approval, collision/revocation handling and authenticated immutable snapshots. Separate migration of Calibration is required before changing its wire/installer profile. The old generated index remains a projection of reviewed v0.1 descriptors only. Do not feed proposals into it.

The `tests_publication` suite is isolated from existing runtime unit tests and uses pinned Core reference fixtures. No duplicate catalogue or approval authority.
